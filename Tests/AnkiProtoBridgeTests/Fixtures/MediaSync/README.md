# Native media-sync protocol fixture

This is a bounded loopback HTTP fixture, not an Anki server implementation.
The test calls `SyncService.liveValue` with a real isolated Rust backend.
Collection download/upload, zstd decoding, media ZIP extraction, media database
updates, image decoding, and Check Media / Check Database are real.

`collection.anki2.zst` was generated by the repository's compiled Rust backend:
open a scratch collection, add a Basic note with fields
`["<img src=\"probe.png\">", "media sync"]` to deck 1, verify Check Database is
empty, close the collection, and compress the SQLite file with `zstd`.
No user's collection, account, or media was used.

`probe.png` is the original placeholder app icon resized to 2 × 2 with `sips`.
The stored ZIP contains entry `0` (that PNG) and `_meta`:
`{"0":"probe.png"}`. `media.zip.zst` is this ZIP compressed with `zstd`.
Its SHA-1 is recorded in `protocol.json`.

Each JSON endpoint's `.zst` file is generated by
`jq -c '.<endpoint>' protocol.json | zstd -o <endpoint>.json.zst`.
Upload's response is literal `OK` (no newline):
`jq -rj '.upload' protocol.json | zstd -o upload.json.zst`.
The server requires collection → begin → changes → ZIP → empty changes →
sanity in that order. Unknown requests fail the test; no status is mocked.
